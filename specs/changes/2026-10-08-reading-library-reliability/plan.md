# 修复阅读与书库交互可靠性

## 概述

修复发现换书的进度身份、首页与搜索请求竞争、动态分页和续读入口。沿用 Riverpod 数据访问与服务器代际隔离，不增加依赖或后端契约。

## 需求

- R1. 阅读器维护当前漫画与章节身份，异步保存捕获当时的位置。
- R2. 搜索与随机分页使用查询代际拒绝过期结果，加载更多互斥，并保留正在展示的收藏变化。
- R3. 用已加载数量推导下一页及需要跳过的重叠条目；按网格实际内容宽度更新页大小。
- R4. 续读条有记录时持续显示，首屏、刷新与分页具有真实的加载和错误反馈。

## 技术决策

- 后端按页号与页大小计算偏移；前端通过已加载数量整除当前页大小得到页号，跳过余数对应的已消费条目，兼容既有接口与发现分页。
- 查询代际与服务器代际同时校验；新的搜索、刷新或重建淘汰旧查询，重复加载更多不重复发请求。
- 分页返回时读取最新列表再追加，避免覆盖请求期间发生的收藏角标变更。
- 页大小更新仅影响下一次请求，首次加载和换种子的异步结果保留最新布局尺寸。

## 实现单元

### U1. 阅读器当前漫画身份

- 文件：`app/lib/screens/reader_screen.dart`、`app/test/reader_screen_test.dart`。
- 方案：切换成功后更新当前漫画身份；初始化、目录重试与保存统一使用当前身份，保存捕获章节与页码。
- 验证：发现连续换书后请求中的漫画与章节归属一致；原有手机定位测试通过。

### U2. 查询顺序与动态分页

- 依赖：U1。
- 文件：`app/lib/providers/comics_providers.dart`、`app/test/comics_providers_test.dart`。
- 方案：查询代际、分页加载状态与失败恢复；动态页大小按已消费数量续页，保留最新已加载列表。
- 测试场景：搜索乱序；刷新与分页竞争；重复触底；分页途中收藏；首次加载期间更新页大小；页大小缩小和扩大直到完整序列。
- 验证：过期成功和失败均不污染当前查询，分页失败后可以继续重试，服务器隔离仍有效。

### U3. 首页与搜索加载反馈

- 依赖：U2。
- 文件：`app/lib/screens/home_screen.dart`、`app/lib/screens/search_screen.dart`、`app/test/home_screen_test.dart`。
- 方案：网格布局使用实际约束更新页大小，滚动加载捕获错误；搜索显示当前查询与重试；移除续读条隐藏计时。
- 验证：续读条超过 3 秒仍显示；加载指示仅在真实请求期间显示；重新搜索和清空关键字行为一致。

## 范围与风险

- 不修改后端，也不加入持续进度上报或本地存储。
- 不为测试引入生产抽象；复用 API 工厂覆写与现有阅读器假图片网络。
- 页大小变化可能令下一次返回少于完整一页，这是兼容既有接口的结果，不影响完整性。
- 本批回归覆盖书库数据在分页期间不发生导入的情形；在线导入快照一致性另行定义。
