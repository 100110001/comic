# 修复阅读与书库交互可靠性

## 问题与目标

发现会话换书后使用初始漫画身份保存进度，导致后续漫画的位置保存失败。首页随机分页与搜索缺少同服务器内的请求顺序保护，改变页大小也可能重复或漏书。首页续读条自动隐藏，与现有规范不一致。

## 需求

- R1. 发现会话切换漫画前和离开时，阅读进度始终属于当时正在阅读的漫画与章节。
- R2. 搜索仅接受最新关键字的结果，刷新后的列表不被旧分页覆盖；重复触底只请求一次。
- R3. 首页页大小随实际网格列数变化，同一种子下已加载漫画保持顺序，后续分页不重复、不遗漏。
- R4. 有阅读记录时首页继续阅读条持续可见，点击保持原有定位行为。
- R5. 请求失败提供可恢复提示，有缓存时继续展示；保留服务器隔离与收藏角标的原地同步。

## 验收示例

- 从漫画 A 切到 B，再切到 C 或返回时，分别保存 B 的章节和页码到 B。
- 先搜索 A 后搜索 B，B 先返回、A 后返回时最终仍展示 B。
- 加载更多期间刷新，旧分页晚到时不改变刷新后的列表。
- 已加载 30 本后每页改为 18 本，继续加载直到全库时漫画序列完整且唯一。
- 在分页请求期间收藏已显示的漫画，响应完成后角标仍保留最新状态。
- 首页等待超过 3 秒仍能点击继续阅读。

## 范围

本批修复既有功能，不变更后端接口或数据库结构。进度本地兜底、后台同步、缩略图、缩放、筛选、离线下载等另行定义；本批保留离开或换书时保存的现有策略。
