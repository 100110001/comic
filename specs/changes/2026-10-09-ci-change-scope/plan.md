# 实施计划

## 概述与范围

减少与改动无关的检查，保留现有代码检查门禁。需求对应定义 R1 至 R4。

## 关键决策

- 两个任务检出后调用同一 PowerShell 脚本；按输出条件执行后续步骤，保留 check 状态并避免增加前置任务启动等待。
- PR 比较事件基准提交与测试合并提交，push 比较 before 与当前提交。仅补取缺失的基准提交，避免下载完整仓库历史。
- 差异禁用重命名识别，跨目录移动同时计入源和目标；无法取得基准时失败，首次 push 的空基准保守检查两边。
- 文档免检采用白名单；未识别文件触发两边。应用与后端目录内部的文档也按目录完整检查，避免误跳过 Markdown 资源。

## 实施单元

### U1. 已完成范围判定与条件检查（PR #53）

- 文件：.github/scripts/ci-scope.ps1、.github/workflows/ci.yml。
- 验证：临时 Git 仓库覆盖文档、应用、后端、混合、未知文件、重命名、删除、空差异、空基准和无效基准；执行仓库五项门禁；云端确认两边完整执行，文档跳过通过本地差异场景验证。
- 初始提交保留过程文档；验证后收割规范，最终 PR 仅留下实现和规范。

## 规范影响

- 更新 specs/project-layout.convention.md：按目录执行门禁，文档白名单免检，未知或共享配置保守检查，范围判断失败不放行。
- 更新 AGENTS.md 的 CI 描述，使其与执行范围一致。

## 延后工作

Ubuntu runner、缓存调整、部分测试选择和并发取消均不在本次范围。
