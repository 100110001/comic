# 尺寸按需读取实施计划

## 范围与决策

取消导入阶段的图片头读取。新图片宽高为空；已有图片仅路径或页码变化才写入，路径变化清空旧尺寸。阅读接口已有前 16 张请求内补齐和同章合并的有界后台任务，继续复用。

用户已确认同名替换检测。阅读请求在返回缓存前读取文件状态，用大小、修改时间、状态变化时间识别版本；首次使用验证既有尺寸，后续复用最多一万条已验证版本。旧后台任务以文件状态与数据库原尺寸、路径为条件回写。保留底层尺寸探测算法，不修改数据库结构。

同步后将数据库已知尺寸写回本地扫描文件；阅读请求不重写整个文件。章节与图片查询按二十本分组，保留数据库对漫画标题的排序规则匹配，重复漫画顺序重查。执行计划确认命中现有索引，无需新增索引。

## 实施单元

### U1：完成按需尺寸、扫描快照和批量查询（PR #77）

- 文件：导入、扫描、同步脚本、章节阅读接口及对应测试。
- 扩展现有测试验证新图空尺寸、重导入零探测零写入、页码重排保留尺寸、路径变更清空尺寸。
- 完成后执行仓库要求的五项门禁。

## 规范影响

- `specs/import-pipeline.spec.md`：同步不读取图片尺寸。
- `specs/reader.spec.md`：尺寸由阅读时补齐，文件版本变化使旧尺寸及旧响应缓存失效。
