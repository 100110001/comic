# 双端页面设计（桌面 / 手机）

## Summary

把漫画应用重构成桌面（Windows/浏览器）与手机两套体验：桌面用左侧边栏导航与单页大图滚轮阅读器，手机用底部"首页/我的"两个 tab 与连续滚动阅读器。两端首页都是"最近阅读卡片 + 全库随机网格"，阅读器都带本章进度条、快速跳转和自动续章。

---

## Problem Frame

当前应用只有一套面向手机竖屏的界面：底部三个 tab、固定宽度的网格、阅读器仅竖向连续滚动。桌面窗口与浏览器里内容利用率低，操作仍按触屏设计，没有滚轮翻页、侧栏或宽屏布局。库数据本身没有可靠的排序依据（标题/作者常残缺或混乱），现有按标题排序的首页放大了这个缺陷。所有页面都没有平台差异，移动端与桌面端共用同一套妥协后的交互。

---

## Key Decisions

| 维度 | 桌面（Windows/浏览器） | 手机 |
|---|---|---|
| 导航 | 左侧边栏（首页/最近阅读/收藏）+ 顶栏搜索 | 底部两个 tab：首页/我的 |
| 首页 | 最近阅读卡片 + 全库随机网格 | 最近阅读卡片 + 全库随机网格 |
| 阅读器 | 单页大图，滚轮翻页 | 竖向连续滚动 |
| 进度与跳转 | 本章进度条 + 拖动跳转 | 本章进度条 + 拖动跳转 |
| 目录 | 侧边面板 | 底部抽屉/全屏列表 |

- **双端两套设计，不是一套自适应。** 输入方式（鼠标键盘 vs 触摸）与屏幕形态差异大，一套界面两端都会妥协；Android/iOS 恒为手机，桌面系统与浏览器按窗口宽度在两种形态间切换。
- **首页默认随机而非排序。** 库数据不可信，随机让乱库也能逛；"发现"页并入首页，移动端由三 tab 精简为两 tab。
- **进度条按本章计算。** 跨章节跳转依赖目录、上一章/下一章与自动续章，不引入整本百分比复杂度。
- **详情页只做双端适配 + 继续阅读按钮。** 不引入依赖库数据的简介/标签/推荐等内容，避免做成空壳。
- **不做库整理。** 随机展示是应对乱库的手段，这轮只做展示层。

---

## Requirements

**双端框架**

- R1. 应用提供桌面与手机两套界面：Android/iOS 恒为手机形态；Windows/Linux/macOS 与 Web 按窗口宽度选择（宽屏桌面、窄屏手机）。
- R2. 桌面导航为左侧边栏（首页/最近阅读/收藏）与顶栏搜索框；手机导航为底部"首页/我的"两个 tab。
- R3. 移除原有"发现"页，随机展示能力并入首页。

**首页**

- R4. 首页顶部展示"最近阅读"卡片，只显示最近读过的一本漫画，含封面与"第 X 话 · 第 Y 页"。
- R5. 点击"最近阅读"卡片直接进入阅读器并定位到记录的章节与页码。
- R6. 首页主体为全部漫画的网格，默认随机顺序展示。
- R7. 没有阅读记录时首页不显示"最近阅读"卡片。

**搜索**

- R8. 桌面版在顶栏提供常驻搜索框；手机版通过首页顶栏搜索图标进入全屏搜索页。

**阅读器（桌面）**

- R9. 桌面阅读器为单页大图模式，鼠标滚轮翻页。
- R10. 阅读器展示本章进度（第 N / M 页），提供可拖动跳转的进度条。
- R11. 章节末尾自动进入下一章，并提供上一章/下一章按钮与章节目录入口。
- R12. 桌面章节目录以侧边面板呈现。

**阅读器（手机）**

- R13. 手机阅读器为竖向连续滚动。
- R14. 手机阅读器展示本章进度条并支持拖动快速跳转。
- R15. 手机阅读器章节末尾自动续章，目录以底部抽屉或全屏列表呈现。

**阅读进度**

- R16. 阅读位置记录保持"每本漫画一条（章节 + 页码）"；离开阅读器时更新为最新位置，自动续章后同样更新。

**详情页**

- R17. 详情页保留封面、作者、收藏开关与章节列表。
- R18. 桌面详情页为"左侧信息 + 右侧章节列表"的并排布局；手机保持纵向布局。
- R19. 有阅读记录时详情页提供"继续阅读"按钮，点击进入阅读器并定位。

---

## Key Flows

- F1. 续读
  - **Trigger:** 用户点击首页"最近阅读"卡片或详情页"继续阅读"按钮。
  - **Steps:** 读取该漫画的记录（章节 + 页码）→ 打开对应章节 → 定位到页码。
  - **Covered by:** R5, R16, R19
- F2. 桌面翻页阅读
  - **Trigger:** 用户在桌面阅读器中滚动鼠标滚轮。
  - **Steps:** 单页切换 → 进度条更新；拖动进度条章内跳转；章末自动进入下一章。
  - **Covered by:** R9, R10, R11
- F3. 手机滚动阅读
  - **Trigger:** 用户在手机阅读器中竖向滑动。
  - **Steps:** 连续滚动 → 进度条随位置更新；拖动进度条章内跳转；章末自动续章。
  - **Covered by:** R13, R14, R15
- F4. 目录切换章节
  - **Trigger:** 用户打开章节目录（桌面侧边面板 / 手机抽屉）。
  - **Steps:** 选择章节 → 打开该章节 → 更新阅读记录。
  - **Covered by:** R12, R15, R16

## Acceptance Examples

- AE1. **Covers R4, R5.** Given 用户最近读过《XXX》第 3 话第 10 页，When 用户打开应用，Then 首页顶部出现《XXX》的"最近阅读"卡片，点击后直接进入第 3 话并定位到第 10 页。
- AE2. **Covers R9, R10.** Given 桌面阅读器打开第 3 话（共 40 页），When 用户滚动滚轮翻到第 10 页，Then 进度条显示 10/40；拖动进度条可跳到本章任意页。
- AE3. **Covers R11, R15.** Given 用户读到某章节最后一页，When 继续翻页/滚动，Then 自动进入下一章节，阅读记录更新为新章节位置。
- AE4. **Covers R1, R2.** Given 同一应用分别在桌面窗口/浏览器与手机运行，When 用户浏览，Then 桌面呈现侧边栏 + 顶栏搜索，手机呈现底部"首页/我的"两个 tab。

## Scope Boundaries

Deferred for later:

- 库整理能力（改名、移动文件夹、清理无效条目）
- 依赖库数据的详情内容（简介、标签、相似推荐）
- 阅读器双页、缩放、阅读方向等交互增强
- 排序与筛选能力（等库数据可靠后）

Outside this round:

- 不做库整理——随机展示是应对乱库的手段

---

## Dependencies / Assumptions

- 依赖上一轮已落地的"每本漫画一条阅读记录"数据模型与最近阅读/收藏接口。
- 假设：首页随机网格在每次进入首页时重新随机，下拉刷新也会重新随机。
- 假设："最近阅读"列表为只读列表，不支持手动移除单条记录。
- 假设：图片预加载、缓存与加载占位等性能细节由规划阶段决定，不在本定义中指定。
