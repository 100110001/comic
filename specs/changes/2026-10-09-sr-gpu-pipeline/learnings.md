# 实现记录

- 研究复核：三处 API 最大项目数、手动重试窗口、轮询等待、初始化和主动清理临时目录必须同步。
- 后台两图合计输入不超过 2000 万像素，超大单图仍独立处理。
- 批次结束后发布，可接受完整且经过校验的部分结果；未开始的新当前页优先，运行中批次不抢占。
- 批次超时是图片数量乘单图配置，不承诺各图独立计时；客户端等待上限改为五分钟。

- 无敏感内容的 251×180 官方样图五份：逐张启动两轮 4657/4615 ms；当前页单独、后台双图两轮 3006/3069 ms。启动批次均为 1、2、2，GPU 子进程并发峰值 1，全部结果通过尺寸校验，主动清空后缓存目录为空。这是小样图吞吐验证，不能证明真实漫画负载曲线平滑。
- 五项门禁全部通过：Dart 格式、Flutter analyze、80 项 Flutter 测试、后端格式及 lint；TypeScript build 通过。
- 用户进一步询问持续入队、不断输出的常驻引擎架构。已说明现有 CLI 固定启动输入列表，小批不能等同于常驻推理；方向选择等待用户回复，草稿未发布 PR、未收割规范。

- 用户明确要求滑动预处理后十页，本单元聚焦窗口契约。小批实验保留在历史提交，最终变更不包含它；常驻 worker 仍是后续引擎改造，不能用小批代替。

- 最终窗口单元复核：提交、轮询和手动重试统一十一项；后端服务仅添加窗口常量，逐图引擎及缓存去重逻辑保持既有实现。
- 更新后五项门禁及 TypeScript build 全部通过；Flutter 80 项测试通过。真实 HTTP 集成验证十一项原图/增强、提交优先级 0—10 与十二项拒绝通过；引擎在该接口验证中替换为确定性任务返回，不把此验证当作新引擎性能测试。
