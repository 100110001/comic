# 实现记录

## U1

- 未使用两维 ResizeImage.exact：它会改变原比例；fit 再 cover 或单宽度方案会让部分封面裁切后放大模糊。公共 provider 在解码回调获取原图宽高后计算 cover/contain/fitWidth 的保比例目标。
- 缓存 key 使用 NetworkImage 原始 key、物理显示尺寸档位与 BoxFit，URL 来源和版本不变；超过 4096 档回退原图。组件取实际受约束尺寸，避免显式宽高超过父约束时过度解码。
- 自审：包装后的解码失败必须清包装 key，源 NetworkImage 自身错误清理只认识源 key；已经增加包装 key 清理。图片 provider 按源、尺寸与 fit 比较相等。
- 真实图片测试：800×400 封面在 128×128 cover 中解码为 256×128，contain 为 128×64；256×2560 长条页按宽 128 解码为 128×1280，32×16 小图不放大。
- flutter analyze 无问题，flutter test 56 项通过。封面入口均已替换，原比例、主题、错误占位及布局保留。

## U2

- 阅读器直到图片主体布局确定后才预加载，显示与当前/前一/后两页共用同一 provider 工厂；首次布局和尺寸档位变化后的回调校验章节与布局代际。
- 桌面 contain 使用 Expanded 内真实宽高，移动 fitWidth 保持长条图完整高度；重试等待实际 provider.evict，移动图片项以原 URL 固定身份。
- 自审发现已有移动滚动偏移在窗口变宽后未重算，桌面切移动也可能返回旧滚动页。现在重建估算偏移并抑制中间页码，定位当前页；桌面→移动→桌面→移动测试确认本机断点不回退。
- 新增缓存命中测试：当前及相邻页面只请求一次，显示不生成原图缓存，同档窗口调整不重复请求。两个阅读形态的重试测试先放入有效尺寸缓存，再确认点击仍驱逐该 key 并真实重发请求。
- 图片描述符解码属于真实引擎异步任务；原假时钟 pumpAndSettle 会饿死任务，测试现在等待真实图片预加载 Future 后再收敛帧，没有固定时间睡眠。
- 自审对未支持的 BoxFit 加原图回退，避免将 fill/none 等误当 contain。
- flutter analyze 无问题，flutter test 60 项通过。无需改变后端、图片源地址、主题、分页或依赖。
