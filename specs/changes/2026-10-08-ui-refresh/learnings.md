# 实现记录

- 采用共享的文字区高度计算，包含系统字体缩放。用户强调移动版后，不足 480px 的手机改为两列；分页仍按实际列数乘六。
- 首页刷新文案区分“换一批”和“刷新结果”，搜索状态不改变关键字。
- 详情窄屏采用单个 CustomScrollView 与懒加载章节 SliverList，避免无界嵌套列表或一次构建全部章节。
- 详情主按钮有阅读进度时续读，没有进度时打开首章节；没有章节且没有进度时禁用。
- 个人列表和设置页限宽，桌面列表提供标题；手机沿用“我的”的三个 tab。

## 规划审查

- 审查指出首章节按钮须处理空章节与续读优先级：已实现三种状态。
- 审查指出两行标题必须考虑字体缩放：卡片与网格共享 TextScaler 高度计算。
- 审查指出搜索结果刷新不应叫“换一批”：已区分文案。
- 审查指出详情窄屏目录需要懒加载 sliver：已采用单滚动容器。

## 实现与渲染审查

- 首轮静态分析发现卡片状态类调用共享静态方法时缺少类名限定，已修正，分析通过。
- 真实书库预览与小屏回归测试发现标题文字区存在像素取整和中文字体余量不足，已取整并预留额外高度。
- 封面元数据在大字体窄卡片中应限制一行并截断，已改为受卡片宽度约束的角标。
- 桌面品牌文字在放大字体时应限制行数，已使用可伸缩文字区域。
- 移动版主题模式三选一应允许换行，已改为互斥 ChoiceChip，偏好语义不变。
- 详情首章节按钮显式从第 0 页开始；空章节禁用；长目录保持懒加载。
- AppBar 标题同样声明中文字体回退栈。
- 首页底部留白随系统字体缩放调整；新增几何位置检查确认 320px、2 倍字体时最后一张卡片可完整滚到续读条上方。
- 静态分析与 37 项测试通过；Web、Windows 和 Android 调试 APK 构建成功。
- Android 构建出现跨盘 Kotlin 增量缓存警告，编译器回退后构建成功；无需修改构建配置。
- 使用示例数据导出手机和桌面 Flutter 渲染截图，预览脚本与数据不纳入产品代码。
