# 漫画软删除实现计划

## 目标与需求

实现 define.md 的 R1–R6：增量导入、缺失软删除、恢复原 ID、统一隐藏与保留历史、失败保护和缓存失效。

## 技术决策

- 漫画增加可空 `deleted_at` 与 `source_root`。初始化为旧库幂等补列；新库直接具备字段。
- 缺失状态在全部内容导入成功后按已解析的漫画 ID 统一事务提交；导入失败不改变删除状态。已删除漫画重新被扫描到后在同一事务恢复。
- 同步显式传入当前库根目录。只标记归属该库的记录；历史记录根据位于当前库下的封面路径确认归属，不能确认的保留并提示。
- 扫描结果为空时拒绝同步，不执行导入或缺失标记，防止空挂载点导致整库隐藏。暂不支持通过清空整个库批量软删除。
- 继续按标题和作者匹配；用实际复用的 ID 判断是否扫描到，避免数据库排序规则与 JavaScript 字符串规则不一致。
- 查询统一排除 `deleted_at` 非空漫画；搜索 OR 条件分组，分页总数、作者作品数与看板数量使用同一可见范围。旧详情、章节、打开目录、收藏及进度写入口拒绝已删除漫画。
- 最近阅读响应附带已删除漫画 ID，客户端只过滤展示，不删除本机待上传断点。离线时沿用本会话已确认的缺失状态；尚未从服务器获知的状态无法离线判断。
- 目录改名后的跨记录迁移、章节和图片级软删除不在本次范围；直接图片静态 URL 不新增数据库鉴权。

## 实现单元

### U1. 漫画软删除与查询一致性

状态：已实现，五项本地门禁通过，待最终 PR。

- 依赖：无。在当前 `codex/comic-soft-delete` 分支完成，遵循用户要求同一分支和目标 master 的最终 PR。
- 文件：数据库结构与初始化、seed/sync、漫画与章节及个人列表接口、看板、客户端 API 和本机最近阅读合并，以及现有相关测试。
- 方法：先完成兼容字段与同步事务，再覆盖各查询入口及客户端合并，最后更新文档。
- 高价值测试：旧记录缺失与恢复、反复同步幂等、失败不变更标记、不同库隔离、空扫描拒绝、作者搜索不绕过删除过滤、旧章节与详情拒绝、客户端保留待同步断点但隐藏已删除条目。
- 验证：从 app 运行规定的格式检查、analyze、test；从 backend 运行 lint、test。测试只使用替身数据库和临时文件，不操作真实漫画库。

## 规范影响

## Spec Impact

- 更新 `specs/import-pipeline.spec.md`：完整成功同步的软删除、恢复、库归属和空扫描保护。
- 更新 `specs/comics-browsing.spec.md`：所有浏览查询与旧详情只提供未删除漫画。
- 更新 `specs/reading-history-and-favorites.spec.md`：隐藏缺失漫画但保留收藏和进度，本机断点遵守已确认的删除状态。
- 更新 `specs/backend-observability.spec.md`：看板只统计可见漫画及其章节图片。

## 风险与验证边界

- 不改变漫画身份匹配，不推断重命名后的历史迁移。
- 非空但内容不完整的成功挂载无法仅靠扫描证明健康；软删除可逆，保留所有内容索引及历史。
- 旧记录封面路径无法归属当前库时不自动软删除。
- 用户已授权继续规划、实现、检查和 PR；整个循环在同一分支完成，收割将规范更新纳入最终 PR。
