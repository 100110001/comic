# 实施计划

## U1：修复发布选择及恢复入口

- 新增选择脚本，读取 GitHub 正式 Release，按稳定版本数值排序并解析本地完整标签提交。
- 工作流从 master 获取流程脚本，push 和 workflow_dispatch 共享入口；手动入口只允许在 master 调用。独立检出目标标签解析出的提交，构建及清单均来自该提交。
- 扩展既有临时仓库集成测试，覆盖压缩合并导致的非祖先标签、乱序列表、草稿/预发布过滤以及拒绝路径；测试不联网。
- 完整运行两项目五项门禁、发布集成测试、工作流语法及脚本语法检查。
- 按用户要求同一分支、同一 PR 完成定义、计划、实现与收割；分阶段提交保留过程记录。

## Spec Impact

更新 specs/versioning.convention.md，说明基线来源、手动恢复入口和原标签源码不变；同步操作文档。

## 边界

不改应用行为、版本文件、签名方式和已有标签；不自动合并或执行发布。
