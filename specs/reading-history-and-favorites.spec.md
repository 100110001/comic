# 阅读记录与收藏

## 职责

提供“我的”页面所需的阅读进度与收藏数据：每本漫画只保留一条最新阅读位置（章节 + 页码），收藏是漫画级别的开关。已同步数据由后端持久化，客户端以本机待同步断点兜底，前端“我的”页展示最近阅读、收藏与收藏作者三个列表，漫画详情页展示收藏状态并允许切换，首页与详情页的继续阅读入口以此数据定位。

非目标：多用户/账号体系、按章节分别保留多个断点、阅读器内的翻页/缩放/方向设置。

## 公开契约

- `PUT /api/comics/:id/progress`，body `{ chapterId, pageNumber }`：记录该漫画的最新阅读位置。`chapterId` 必须属于该漫画，否则拒绝。同一漫画重复上报时覆盖旧记录，不产生第二条。
- `POST /api/comics/:id/favorite`：收藏该漫画；已收藏时重复调用无副作用。
- `DELETE /api/comics/:id/favorite`：取消收藏；未收藏时重复调用无副作用。
- `GET /api/mine/recent`：最近阅读列表，每本漫画一条，按最近更新时间倒序；每条含漫画信息、`chapterId`、章节标题与 `pageNumber`。
- `GET /api/mine/favorites`：收藏列表，按收藏时间倒序，含漫画信息与话数/图片数。
- `GET /api/comics/:id` 的响应包含 `favorited: boolean` 与 `progress`（有记录时为 `{ chapterId, pageNumber }`，否则为 `null`）。
- `GET /api/comics` 列表接口的每条记录包含 `favorited: boolean`。
- `GET /api/favorite-authors`：收藏作者列表（作者名 + 作品数，按收藏时间倒序）。
- `POST /api/favorite-authors`（body `{ author }`）：收藏作者，幂等。
- `DELETE /api/favorite-authors`（body `{ author }`）：取消收藏作者。
- `GET /api/comics/:id` 的响应包含 `authorFavorited: boolean`。

页码为 0 起始（对应章节图片数组下标）。

- 详情主阅读按钮：有进度时为“继续阅读”，定位到原章节与页码；无进度且有章节时为“开始阅读”，打开首章节第 0 页；无进度且无章节时为“暂无章节”，按钮禁用。
- 详情宽度不足 720px 时头部与章节目录在同一滚动页面内，长标题不挤掉目录；宽屏采用可分别滚动的详情面板与章节栏。章节按既有顺序懒加载，当前章节有文字提示。

## 不变量

- 每本漫画在 `reading_progress` 中至多一条记录。
- 收藏不区分章节，`favorites` 中每本漫画至多一条。
- 阅读进度与收藏以数据库 ID 关联漫画；重新增量导入不会改变既有 ID（见导入流程 spec），因此记录跨重新导入保持有效。
- 应用内删除漫画的功能已下线：前端详情页无删除入口，后端无对应路由。

## 说明

- 阅读记录与收藏是单机、单用户级别数据，无账号体系，不按用户区分。
- 阅读器有效位置变化先保存本机断点，离开、换书和后台时补传；启动、恢复前台和切回对应服务器时重试。服务器上传失败保留本机记录，阅读器提供手动同步入口。
- 首页和最近阅读优先展示当前服务器的本机待同步项，按本机保存顺序倒序置顶，并按漫画去重；远端尚未响应或失败时，已有本机项仍可用于续读。其他服务器的本机项不显示但保留。
- 详情续读优先使用章节仍在目录中的本机待同步位置；失效的本机章节回退远端进度，无进度时采用首章入口。
- 同步确认只移除已上传的相同版本；已同步断点不额外保留在本机历史中，没有待同步项时以远端位置为准。
- 本机保存后续读入口立即反映当前位置；同步成功后重新拉取最近阅读与漫画详情，翻页更新本机位置不重复请求这两个远端查询。
- 首页/搜索页从详情页返回后，会原地同步卡片的收藏角标，不重排列表。
- "最近阅读"列表项点击后进入漫画详情页（续读入口为详情页的"继续阅读"按钮与首页悬浮条）。
- 作者收藏按名字去重；详情页作者名旁可切换收藏；"我的"页与桌面侧栏提供"收藏作者"列表，点击进入该作者的漫画列表。
