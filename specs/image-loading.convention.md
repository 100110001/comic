# 图片加载与缓存

## 职责

为封面、阅读页和相邻页预加载提供统一解码与缓存身份，减少小尺寸展示大图时的原生解码内存，同时保持原比例、清晰度、主题、错误占位和既有布局。

后端原图传输通过共享并发额度降低同时读盘的峰值，适用于机械硬盘来源。

## 规则

- 原始文件路径转图片 URL 时按路径段编码，目录分隔符保留；`#`、`%`、`?` 等字符属于文件名，不得变成 URL 片段或查询。版本参数单独追加，接口已编码的 URL 不重复编码。
- 解码尺寸来自实际受约束的显示区域乘设备像素比，不能把逻辑像素直接当物理像素；图片加载不改变占位尺寸。
- 封面与阅读图片在首帧解码前保持占位，包括尚未收到字节进度的阶段；完成后按 UI 动效约定呈现。已知有效总字节数时，阅读图片显示真实下载进度；失败仍进入原有错误与重试流程。
- 原生端向上使用有限像素档位：128、192、256、384、512、768、1024、1536、2048、3072、4096。同一档位复用缓存，超出最大档位、无有效尺寸或未支持的显示模式时回退原图，不硬性压缩高清屏所需分辨率。
- 封面按 `BoxFit.cover` 裁切需求保比例解码，不能拉伸原图。分页适应窗口采用 contain，适应宽度及连续阅读采用 fitWidth 并保留完整高度；双页按各页槽位计算显示、预加载与重试尺寸。实际大小使用原图，不按视口缩小解码。解码不放大超过原图尺寸。
- 缓存身份包含完整源图片身份、物理显示尺寸档位和显示模式。增强结果 URL 同样保留原图版本、模型参数与缓存代际所决定的身份。不得移除 URL 中的服务器地址或文件版本参数，不依据全局当前来源改写旧图片地址。
- 显示、预加载和重试由同一图片 provider 工厂产生缓存身份；不得为预加载解码原图、显示时另解码缩图。阅读器预加载范围与定位规则见 `specs/reader.spec.md`。
- 包装图片的加载失败清理尺寸包装键；手动重试等待实际 provider 缓存驱逐后重建，而非仅驱逐源 `NetworkImage` 键。
- 网络原始图片字节、图片来源及全局 LRU 缓存预算沿用既有实现，不新增客户端图片磁盘缓存或服务器缩略图接口。可选超分的后端衍生缓存独立于原图加载，契约见 `specs/super-resolution.spec.md`。

## 平台边界

- Web 使用浏览器网络图片解码，保持原始 provider，不承诺与原生端相同的解码内存收益。
- 解码优化只降低解码像素开销，不减少下载的网络原始字节。极端宽高比或需要原图分辨率的场景可能仍使用原图大小。

## 后端原图传输

- `/static` 在进入静态文件处理前共享同一后端进程的传输额度，默认同时传输一张，其余按到达顺序排队。`IMAGE_MAX_CONCURRENT_READS` 可配置正整数并发数，缺失或无效时为 1，重启后生效。
- 活动传输在响应完成或连接断开时释放额度；等待中的连接断开后不再进入文件处理。失败、304 和 404 不阻塞后续请求，成功响应保留原有一小时缓存策略。
- 最多排队 256 个请求，等待上限 60 秒；队列满或等待超时返回 503、`Retry-After: 1` 与 `Cache-Control: no-store`。单次传输超过 120 秒断开，避免慢连接永久占用额度。
- 元数据 API 不占传输额度。限制不涵盖扫描、超分任务和增强文件的磁盘访问，也不跨后端进程合并；它降低原图 HTTP 传输并发，不减少总读取量或保证硬盘整体只有一个 I/O。
- 图片尺寸探测采用有界异步图片头读取，按需扩展读取范围；不为获取宽高同步读取整章文件。不可识别或读取失败时保留未知尺寸，不使其他图片失败。
