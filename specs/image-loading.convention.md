# 图片加载与缓存

## 职责

为封面、阅读页和相邻页预加载提供统一解码与缓存身份，减少小尺寸展示大图时的原生解码内存，同时保持原比例、清晰度、主题、错误占位和既有布局。

## 规则

- 解码尺寸来自实际受约束的显示区域乘设备像素比，不能把逻辑像素直接当物理像素；图片加载不改变占位尺寸。
- 原生端向上使用有限像素档位：128、192、256、384、512、768、1024、1536、2048、3072、4096。同一档位复用缓存，超出最大档位、无有效尺寸或未支持的显示模式时回退原图，不硬性压缩高清屏所需分辨率。
- 封面按 `BoxFit.cover` 的裁切需求计算保比例解码目标，确保裁切后的短边清晰度，不把原图拉伸成卡片比例。桌面阅读采用 `contain`，移动阅读采用 `fitWidth` 并保留长条图完整高度；解码不放大超过原图尺寸。
- 缓存身份包含完整源图片身份、物理显示尺寸档位和显示模式。增强结果 URL 同样保留原图版本、模型参数与缓存代际所决定的身份。不得移除 URL 中的服务器地址或文件版本参数，不依据全局当前来源改写旧图片地址。
- 显示、预加载和重试由同一图片 provider 工厂产生缓存身份；不得为预加载解码原图、显示时另解码缩图。阅读器预加载范围与定位规则见 `specs/reader.spec.md`。
- 包装图片的加载失败清理尺寸包装键；手动重试等待实际 provider 缓存驱逐后重建，而非仅驱逐源 `NetworkImage` 键。
- 网络原始图片字节、图片来源及全局 LRU 缓存预算沿用既有实现，不新增客户端图片磁盘缓存或服务器缩略图接口。可选超分的后端衍生缓存独立于原图加载，契约见 `specs/super-resolution.spec.md`。

## 平台边界

- Web 使用浏览器网络图片解码，保持原始 provider，不承诺与原生端相同的解码内存收益。
- 解码优化只降低解码像素开销，不减少下载的网络原始字节。极端宽高比或需要原图分辨率的场景可能仍使用原图大小。
