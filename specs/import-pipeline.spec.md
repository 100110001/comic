# 漫画导入流程

## Responsibilities

将磁盘上的漫画文件夹扫描并导入数据库，供阅读应用浏览和阅读。导入是增量式的：已存在的内容复用原有 ID，只新增缺失内容；磁盘上消失的漫画只提示、不删除，避免外置存储未挂载时被误判为全部删除。

## Invariants

- 漫画按 `(title, author)` 匹配复用；章节按 `(comic_id, title)`；图片按 `(chapter_id, filename)`。
- 每次导入都会用扫描顺序整体覆写该漫画下所有章节的 `sort_order` 与章节下所有图片的 `page_number`，中间插入新内容不会打乱既有顺序。
- 已存在记录的数据库 ID 在重新导入时保持不变。
- 漫画首次入库时间在创建记录时保存，重复同步不改变；最近入库排序不以文件修改时间或后续章节更新为依据。
- 扫描生成的漫画、章节和图片路径保留配置的漫画库入口（转为绝对路径），不将
  junction 或符号链接替换为真实目录，以兼容静态 URL 和目录归属校验。
- 数据库中存在但磁盘上找不到对应文件夹的漫画：导入输出提示，不自动删除数据库记录。
- 初始化不再清空 `comics`/`chapters`/`images` 三张表；`npm run setup` 可重复执行且幂等。
- 导入成功后使本项目的 Redis 缓存整体失效，但不清空 Redis 数据库中的其他应用数据；Redis 不可用时只跳过缓存失效，不回滚已完成的数据库导入。
- 导入图片时读取当前文件的尺寸，并与路径、页码一起保存；重新扫描同名图片覆盖旧尺寸，无法读取尺寸时保存为空，供阅读接口后续尝试补齐。
- 封面取第一章第一张图；已存在漫画的封面在扫描到的封面变化时同步更新。

## Notes

- 匹配依据是解析自文件夹名的 title/author 与图片文件名，因此重命名文件夹会被视为新漫画，旧记录保留并提示缺失，需手动清理。
- 重复导入不会修复原文件已删除、改名或改变扩展名留下的旧索引。整理旧索引是独立操作：确认文件确实缺失、先备份，并核对有效章节、收藏和进度；不能用自动删除代替这些检查。
- MySQL 唯一键对 `author IS NULL` 的行不去重，作者为空的漫画由导入脚本在 JS 侧匹配。
- 收藏与阅读进度表的外键在漫画被删除时级联清理（当前应用内已无删除入口）。
- `npm run setup` 先调用 `db:init`，再调用 `comics:sync`。同步依次扫描、导入本次扫描结果和可选清缓存；扫描或导入失败时停止。`data/scan.json` 保留供检查，不作为后续同步的输入。
- `comics:organize` 独立整理磁盘目录，不自动导入数据库：先展开 original，再将无子目录且无同名目标的根图片归入第1話。默认处理 COMIC_ROOT 的漫画子目录，`--comic` 指定单漫画，`--root` 指定库，两者互斥；显式目标不依赖 COMIC_ROOT。`--dry-run` 仅预览相同操作，不写入。
- 整理不覆盖同名目标、不合并同名目录，只删除已清空的 original。冲突保留原内容并返回失败；单个漫画出错后继续其余漫画，不回滚已完成移动。库内链接目录不跟随，漫画及 original 的直接子项含符号链接时拒绝整理。整理后需同步，旧索引仍遵循不自动删除规则。
- `comics:fix-chapter-order` 无需重新扫描磁盘，按标题修复数据库章节顺序及首章首图封面，成功后可选清缓存；成功或失败均释放数据库连接。
- 需要脱离导入流程手动失效本项目缓存时，运行 `npm run cache:clear`；Redis 不可用时该命令以失败状态退出。
