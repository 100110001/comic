# 漫画导入流程

## Responsibilities

将磁盘上的漫画文件夹扫描并导入数据库，供阅读应用浏览和阅读。导入是增量式的：已存在的内容复用原有 ID，只新增缺失内容；磁盘上消失的漫画只提示、不删除，避免外置存储未挂载时被误判为全部删除。

## Invariants

- 漫画按 `(title, author)` 匹配复用；章节按 `(comic_id, title)`；图片按 `(chapter_id, filename)`。
- 每次导入都会用扫描顺序整体覆写该漫画下所有章节的 `sort_order` 与章节下所有图片的 `page_number`，中间插入新内容不会打乱既有顺序。
- 已存在记录的数据库 ID 在重新导入时保持不变。
- 数据库中存在但磁盘上找不到对应文件夹的漫画：导入输出提示，不自动删除数据库记录。
- 初始化不再清空 `comics`/`chapters`/`images` 三张表；`npm run setup` 可重复执行且幂等。
- 封面取第一章第一张图；已存在漫画的封面在扫描到的封面变化时同步更新。

## Notes

- 匹配依据是解析自文件夹名的 title/author 与图片文件名，因此重命名文件夹会被视为新漫画，旧记录保留并提示缺失，需手动清理。
- MySQL 唯一键对 `author IS NULL` 的行不去重，作者为空的漫画由导入脚本在 JS 侧匹配。
- 收藏与阅读进度表的外键在漫画被删除时级联清理（当前应用内已无删除入口）。
